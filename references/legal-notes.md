# 公开发布前的合规清单

> 经验性建议，不是法律意见。真要商业化、出周边、做付费产品，请找律师。

## 风险分级

| 内容 | 风险 | 说明 |
|---|---|---|
| scripts/ 全部代码 | 🟢 低 | 自己写的，通用工具（≈curl + 本地 JSONL 管理），MIT 开源即可 |
| 检索词表、源站清单、抽取规则 | 🟢 低 | 事实与方法，无著作权 |
| 短句语录 + 场景 + 出处链接 | 🟡 中低 | 即兴口述可构成口述作品；短句独创性弱且已广泛传播，属"适当引用"，但公开传播超出"个人使用"范围 |
| 他的照片 / 表情包 / 视频 / 音频 | 🔴 高 | 肖像权 + 音视频著作权，别放仓库，只放原链接 |
| 大段搬运盘点文章（凤凰网、游戏矩阵等） | 🔴 高 | 整段复制媒体稿，明显侵权；只能摘短句 + 链接 + 署名 |
| 姓名/出生年月/籍贯/收入经历 | 🟡 中 | 已公开报道的个人信息，合理范围内处理一般 OK；但**不要**再加住址、联系方式、身份证、家人信息 |
| 用他的声音/形象做 AI 克隆、商用周边 | 🔴 高 | 声音权、肖像权、商业化，别碰 |
| 仓库名/品牌名含 "coke" | 🟡 中 | COKE 是可口可乐注册商标。个人非商业项目、描述性使用通常没事，但别做商业化、别起成产品品牌 |

## 上 GitHub 前的 6 条减法

1. **代码与数据分离**：`scripts/` + `references/` 开源（MIT）；`data/quotes.jsonl` 默认 `.gitignore` 掉，仓库里只留 `seeds.example.jsonl`（结构示例，字段为空）。想公开数据就单独放一个仓库，随时可删。
2. **导出用公开发布档**：`corpus.py export --public`，只出已复核 + 置信 ≥0.7 的条目，剥掉内部备注，自动附免责声明。
3. **不放任何图片/音视频**，只放 URL。README 也不要用他的头像当封面。
4. **README 顶部写清**：非官方项目、仅个人学习与检索研究、非商业、内容著作权归原作者、与当事人及可口可乐公司无关联、侵权请联系删除（留邮箱或开 issue 模板）。
5. **留 DMCA/下架通道**：`.github/ISSUE_TEMPLATE/takedown.md` + README 里写明"48 小时内处理"。这点是平台判断善意的关键。
6. **抓取脚本保持克制**：只抓公开静态页、限速、不登录不绕验证码、不做批量下载视频。现在的 `fetch_page.py` 就是这个尺度，别再加"抖音批量下载器"这类功能。

## 建议的授权方式

- 代码：MIT
- 数据/文档：CC BY-NC-SA 4.0（署名、非商业、相同方式共享），或直接声明"数据仅供个人学习，禁止商用"
- `NOTICE.md`：列出内容来源平台（抖音/B站/微博/百科站点等）并说明仅作引用

## 一句话结论

**工具能上，数据要瘦身上。** 开源"怎么采集、怎么整理"这件事完全没问题；开源"他说的每一句话"的全文库，性质就从工具变成内容分发了——把数据脱到"短句 + 出处链接 + 非商业声明"这一层，风险就可控。
